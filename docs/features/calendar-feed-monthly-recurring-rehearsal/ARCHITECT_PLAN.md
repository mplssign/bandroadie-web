## 1. Feature Slug

`bug/calendar-feed-monthly-recurring-rehearsal`

## 2. Problem Summary

Band calendar subscription output generated by `supabase/functions/calendar-feed/index.ts` does not include dependable monthly recurring rehearsal instances for external iCal/webcal consumers. The current feed emits one VEVENT per fetched rehearsal row and does not include recurrence semantics (`RRULE`) or recurrence expansion logic. As a result, monthly recurring series are missing whenever only a parent recurring row is available (or child instance materialization is incomplete), even though in-app calendar rendering can still work from stored rows.

## 3. Root Cause (+ confidence level)

Primary root cause: `calendar-feed` is recurrence-unaware.

- Confirmed behavior in code:
  - Rehearsal query selects only `id, date, location, start_time, end_time, notes, band_id, bands(name)`.
  - It does not select or process `is_recurring`, `recurrence_frequency`, `recurrence_days`, `recurrence_until`, or `parent_rehearsal_id`.
  - VEVENT generation always emits a single non-recurring event per row (no `RRULE`, no parent-child expansion).
- Confirmed failure mode:
  - **Failure Mode 1 (monthly branch missing): confirmed in practice because there is no recurrence branch at all.**
  - **Failure Mode 4 (child instances not generated/available to feed): feed has no fallback path and therefore emits no monthly future instances from parent metadata.**
- Not confirmed as root cause in this function:
  - RRULE malformed monthly logic (there is no RRULE code currently).
  - recurrence_days[] format mismatch in feed path (not used at all by current feed).

Confidence: **HIGH** for code-level root cause in `calendar-feed`; **MEDIUM** for environment-specific reason weekly appears to work while monthly does not (likely data shape differences between series).

## 5. Existing System Analysis (data flow: rehearsal saved → feed request → iCal output)

1. Rehearsal save path (Flutter):
   - `lib/features/events/events_repository.dart` generates recurring rehearsal dates (including explicit monthly calendar-month logic).
   - It inserts parent + child rows in `rehearsals` and links children via `parent_rehearsal_id`.
2. Feed request path:
   - External client calls `calendar-feed` with token.
   - Function resolves subscriber token to band scope and include flags.
   - Function queries `rehearsals` rows by `band_id` and date cutoff.
3. iCal output path:
   - `generateCalendar()` emits one VEVENT per returned rehearsal row.
   - No recurrence metadata is emitted and no recurrence expansion is performed.

Implication:

- Feed correctness currently depends entirely on child rows already existing in `rehearsals`.
- If only parent recurring rows exist (or child rows are incomplete), monthly recurring series are absent from subscription clients.

## 6. Proposed Solution

Implement recurrence-aware rehearsal emission in `supabase/functions/calendar-feed/index.ts` with the smallest safe diff:

1. Extend rehearsal query/shape to include recurrence fields:
   - `is_recurring`, `recurrence_frequency`, `recurrence_days`, `recurrence_until`, `parent_rehearsal_id`
2. In VEVENT generation, branch for recurring parent rows (`is_recurring = true` and `parent_rehearsal_id is null`):
   - Emit one parent VEVENT with `RRULE`.
   - Map frequencies:
     - `weekly` -> `FREQ=WEEKLY`
     - `biweekly` -> `FREQ=WEEKLY;INTERVAL=2`
     - `monthly` -> `FREQ=MONTHLY`
   - Map `recurrence_days` indices (0=Sun..6=Sat) to ICS BYDAY tokens (`SU,MO,TU,WE,TH,FR,SA`).
   - If `recurrence_days` present, include `BYDAY=...`.
   - If `recurrence_until` present, include `UNTIL=...` (end-of-day UTC-safe formatting).
3. Skip child rows (`parent_rehearsal_id != null`) when parent RRULE is emitted to prevent duplicate events.
4. Keep non-recurring rehearsal rows on the current single-instance VEVENT path.
5. Add guarded fallback:
   - If a recurring parent has invalid/missing recurrence metadata, emit a one-off VEVENT rather than dropping it.

Rationale:

- Fixes monthly omission at feed source.
- Preserves weekly/biweekly behavior while making recurrence explicit and standards-compliant for iCal consumers.
- Minimal scope: edge function only.

3. Add RRULE builder supporting:

   - skip recurring children
